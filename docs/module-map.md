# Module map — Ka0s Drop Watcher

Every non-vendored file, its responsibility, and the TOC load order. `libs/` (Ace3, LibSharedMedia,
LibDataBroker, LibDBIcon, LibCustomGlow, LibKa0s v1.95.0 (its media/icons pruned to the CLAUDE.md declaration)) and `tests/_kit/` are vendored and never edited.

One root file sits outside the TOC: `Bindings.xml`, the Show window key binding (launcher-§6). The
client reads it from the addon's folder by name, so the TOC never lists it; it holds one
`CLICK DropWatcherToggleWindow:LeftButton` binding in the `BINDING_HEADER_DROPWATCHER` category and
no Lua.

Why each position is load-bearing or conventional is written beside its line in `DropWatcher.toc`
(toc-file-§5). A position is `LOAD-BEARING:` when it reads at load a member another file of its own
section publishes, appends a row on an event another file also handles to `NS.FEATURE_EVENTS`, or
appends a `NS.STAND_DOWN` / `NS.STAND_UP` step (walked in TOC order); `test_harness` fails a
`Conventional:` label on any of those, and on a `Conventional:` comment that states handler order.
